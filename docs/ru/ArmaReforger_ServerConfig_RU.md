# Конфиг выделенного сервера Arma Reforger — полное руководство

**Версия игры, на которой проверено:** Arma Reforger 1.6.0.119 (engine 192142, dedicated server build 2026-01-23).
**Формат:** JSON. Файл обычно называется `server.json` и передаётся серверу как `-config server.json`.

---

## 0. Как пользоваться этим документом

Документ рассчитан на две аудитории одновременно.

**Если вы человек** — читайте разделы 1–3, затем найдите нужный параметр в разделе 5.
Разделы 6–7 показывают, как выглядит готовый конфиг для типовых задач.

**Если вы языковая модель, которой поручили собрать `server.json` по описанию** —
работайте так:

1. Прочитайте раздел 4 (жёсткие правила). Не нарушайте их ни при каких обстоятельствах.
2. Возьмите шаблон из раздела 6 и меняйте **только** те поля, которые относятся к задаче.
3. Каждое значение сверяйте с разделом 5: там указаны тип, допустимый диапазон и
   значение по умолчанию. Не выдумывайте поля, которых нет в разделе 5 — движок
   их молча проигнорирует (или, при неверном типе, откажется стартовать).
4. Поле `game.scenarioId` берите **только** из
   [`ArmaReforger_Scenarios_RU.md`](ArmaReforger_Scenarios_RU.md) — не сочиняйте GUID.
5. Если данных для какого-то поля в запросе нет — ставьте значение по умолчанию
   из раздела 5 и перечислите принятые допущения в ответе.

**Что в этом документе проверено, а что нет.** Раздел 5 собран из трёх независимых
источников, и для каждого параметра указан источник:

- **`[вики]`** — официальная страница BI «Arma Reforger: Server Config»
  (ревизия от 2025-03-23). Это единственное публичное описание формата.
- **`[бинарь]`** — список имён ключей, извлечённый из строк
  `ArmaReforgerServer.exe` сборки 1.6.0.119. Это точный перечень того, что читает
  конкретно эта версия сервера. Такой ключ существует, но его семантика может быть
  не описана публично.
- **`[практика]`** — наблюдалось в реальном конфиге и в логах работающего
  выделенного сервера.

Параметры, помеченные `[бинарь]` без `[вики]`, существуют, но **не документированы**.
Используйте их осторожно и не выдумывайте им значения — берите те, что приведены здесь,
либо не указывайте поле вовсе.

## 1. Минимум, который нужно понять

1. **Формат — плоский JSON.** Никаких комментариев, никаких висячих запятых,
   никаких одинарных кавычек. Файл с синтаксической ошибкой не будет прочитан.
2. **Ключи регистрозависимы.** `maxPlayers` работает, `maxplayers` — нет.
   Это прямо оговорено в вики и подтверждается поведением сервера.
3. **Типы важны.** Числа — без кавычек (`2001`), строки — в кавычках (`"2001"`),
   булевы — `true`/`false` без кавычек. Вики формулирует это как
   «значения — строки, если не указано иное», но фактически числовые и булевы поля
   должны быть числами и булевыми: конфиг проверяется по встроенной JSON-схеме,
   и при несоответствии сервер пишет
   `Server Config file is Invalid - cannot start server!` и завершается.
4. **У сервера есть встроенная валидация по схеме.** В логе при успешном старте видно:
   ```
   BACKEND : Loading dedicated server config.
   BACKEND : Server config loaded.
   BACKEND : JSON Schema Validation:
   BACKEND : JSON is Valid
   ```
   Если вместо `JSON is Valid` появилось сообщение об ошибке — сервер не запустится.
   Строка `Server Config file is Invalid - cannot start server!` — это вердикт.
5. **Один сервер — один сценарий.** Ротации миссий в Arma Reforger нет.
   Чтобы сменить миссию, нужно менять `game.scenarioId` и перезапускать сервер.
6. **Только один `game`.** Нельзя описать несколько наборов настроек в одном файле.

## 2. Обязательные и необязательные поля

Строго обязательных полей в схеме почти нет — практически всё имеет значение
по умолчанию. Но без следующих полей сервер либо не стартует, либо стартует
в бесполезном состоянии:

| Поле | Почему важно |
|---|---|
| `game.scenarioId` | Без него серверу нечего загружать. Единственное поле, которое обязано быть осмысленным. |
| `game.name` | Имя в браузере серверов. Полезно всегда; максимум 100 символов. |
| `game.maxPlayers` | Если не задать — берётся значение по умолчанию. |
| `a2s.address` | Вики помечает как **required**. На практике пустая строка работает (см. §5.2). |
| `rcon.address` + `rcon.password` | Нужны **только если** вы хотите RCON. Без пароля RCON не поднимется. |

Поля `bindAddress`, `bindPort`, `publicAddress`, `publicPort` вики прямо советует
**не указывать**: сервер сам определит публичный адрес и возьмёт порт 2001.
Указывайте их только при нестандартной схеме проброса портов.

## 3. Анатомия файла

```
{
  ├─ bindAddress, bindPort, publicAddress, publicPort     ← сеть (обычно не нужны)
  ├─ a2s        { address, port }                         ← Steam-запросы (мониторинг)
  ├─ rcon       { address, port, password, ... }          ← удалённая консоль
  ├─ game       {                                         ← всё про саму игру
  │    ├─ name, password, passwordAdmin, admins
  │    ├─ scenarioId, maxPlayers, visible
  │    ├─ crossPlatform, supportedPlatforms
  │    ├─ mods [ { modId, name, version, required } ]
  │    ├─ gameProperties { ... }                          ← настройки геймплея
  │    └─ [ session/database поля ]                       ← см. §5.7
  └─ operating  { ... }                                   ← поведение сервера
}
```

Порты по умолчанию, которые нужно открыть:

| Порт | Протокол | Назначение | Обязателен |
|---|---|---|---|
| 2001 | UDP | игровой (`publicPort`) | да |
| 17777 | UDP | A2S / Steam-запросы (`a2s.port`) | нет |
| 19999 | UDP | RCON (`rcon.port`) | нет |

## 4. Жёсткие правила (соблюдать обязательно)

1. **`scenarioId` всегда с GUID.** Формат: `{16 hex}Missions/Имя.conf`.
   Список — в [`ArmaReforger_Scenarios_RU.md`](ArmaReforger_Scenarios_RU.md).
   Для модовой миссии GUID берётся из `<Миссия>.conf.meta`, поле `Name`.
2. **`modId` — это GUID мода без фигурных скобок и без дефисов**, ровно 16 hex-символов.
   Он лежит в `addon.gproj` в строке `GUID "..."`. Пример: `"5DBD560C5148E1DA"`.
   Не путайте с `ID` — это короткое текстовое имя проекта, оно не подходит.
3. **Ключ называется `modId`, а не `modID`.** Выводы вики противоречат её же примеру;
   правильна форма `modId`, и она подтверждена примером на той же странице.
4. **`serverMinGrassDistance` принимает либо `0`, либо значение из диапазона `50..150`.**
   Значения 1–49 недопустимы.
5. **`rcon.password` не может содержать пробелы и должен быть не короче 3 символов.**
   `game.passwordAdmin` — тоже без пробелов.
6. **`fastValidation` для публичного сервера — всегда `true`.**
   Вики выделяет это отдельным предупреждением.
7. **`supportedPlatforms` — только три допустимых значения:**
   `PLATFORM_PC`, `PLATFORM_XBL`, `PLATFORM_PSN`.
   Допустимые комбинации: либо только PC, либо PC + все консоли.
   Ванильный сервер не может быть «PC + только Xbox». Для сервера с модами
   PlayStation не добавляется (см. §5.5.1).
8. **`maxPlayers`: 1..128.**
9. **Порты: 1..65535.**
10. **Не используйте старые имена полей.** До версии 0.9.8.73 они назывались иначе,
    и старые конфиги с ними не работают:

    | Сейчас | Было до 0.9.8.73 |
    |---|---|
    | `bindAddress` | `gameHostBindAddress` |
    | `bindPort` | `gameHostBindPort` |
    | `publicAddress` | `gameHostRegisterBindAddress` |
    | `publicPort` | `gameHostRegisterPort` |
    | `game.passwordAdmin` | `passwordAdmin` (в корне) |
    | `game.maxPlayers` | `playerCountLimit` |
    | `game.supportedPlatforms` | `supportedGameClientTypes` |
    | объект `a2s` | `a2sQueryEnabled` + `steamQueryPort` |

    > ⚠️ Это не теоретическое предупреждение. Старые конфиги и шаблоны, написанные
    > до 0.9.8.73, **до сих пор встречаются** с устаревшими именами:
    > `gameHostBindAddress`, `gameHostBindPort`, `gameHostRegisterBindAddress`,
    > `gameHostRegisterPort`, а также `dedicatedServerId` и `region`.
    > Не берите такой файл за образец.
    >
    > Это проверено, а не предположено: в бинарнике сборки 1.6.0.119 строк
    > `gameHostBindAddress`, `gameHostBindPort`, `gameHostRegisterBindAddress`,
    > `gameHostRegisterPort` **нет ни одной**, а поля `dedicatedServerId` и `region`
    > встречаются только в коде обращения к бэкенду (REST API), но не в схеме
    > серверного конфига. Проверить самостоятельно можно скриптом
    > [`tools/probe-keys.ps1`](../../tools/probe-keys.ps1).
    >
    > **На 1.8.0.13 картина уже, чем «их нет», и это стоит знать, прежде чем доверять поиску
    > по строкам.** Четырёх имён `gameHost*` в этом исполняемом файле по-прежнему нет, но
    > `playerCountLimit`, `supportedGameClientTypes` и `dedicatedServerId` в нём
    > **встречаются** — внутри пула имён ключей, где есть также `operating`, `a2s` и `rcon`,
    > и в диагностической строке про дескриптор `Room`/сессии. Принимает ли их по-прежнему
    > схема серверного конфига, **не выяснено**: совпадение подстроки в исполняемом файле не
    > доказывает ничего ни в ту, ни в другую сторону. В таблице выше ничего не меняется —
    > используйте текущие имена. Проверено командой
    > [`tools/verify-against-install.mjs`](../../tools/verify-against-install.mjs).

## 5. Справочник параметров

### 5.1 Корень

| Ключ | Тип | По умолч. | Источник | Описание |
|---|---|---|---|---|
| `bindAddress` | string | пусто → `0.0.0.0` | `[вики]` | IP, к которому привязан игровой сокет. Оставьте пустым. IPv6 не поддерживается. |
| `bindPort` | number 1..65535 | 2001 | `[вики]` | UDP-порт игрового сокета. Лучше не указывать — возьмётся равным `publicPort`. |
| `publicAddress` | string | пусто → автоопределение | `[вики]` | IP, регистрируемый в бэкенде. Пусто = определить автоматически (рекомендуется). Принимает литерал `"local"`. **Публичный IP здесь ломает вход из локальной сети — см. замечание ниже.** |
| `publicPort` | number 1..65535 | 2001 | `[вики]` | UDP-порт, регистрируемый в бэкенде. Если сервер за NAT — это внешний порт проброса. |
| `a2s` | object | — | `[вики]` | Секция Steam Query. См. §5.2. |
| `rcon` | object | — | `[вики]` | Секция удалённой консоли. См. §5.3. |
| `game` | object | — | `[вики]` | Всё про игру. См. §5.4. |
| `operating` | object | — | `[вики]` | Поведение сервера. См. §5.6. |
| `serverId` | — | — | `[бинарь]` | Присутствует в схеме 1.6.0.119, публично не документирован. Не указывайте. |
| `ownerType` | — | — | `[бинарь]` | То же. |

> ### ⚠️ Публичный IP в `publicAddress` ломает вход с локальной сети
>
> **Если в `publicAddress` указан внешний (публичный) IP, а сервер стоит на домашней
> машине, — зайти на него из той же локальной сети вы, скорее всего, не сможете.**
> Проверено на практике: вход не работал до тех пор, пока на роутере не было настроено
> перенаправление с публичного IP на локальный.
>
> **Почему так.** Сервер регистрирует в бэкенде именно тот адрес, который вы указали.
> Игровой клиент и браузер серверов получают **один и тот же** адрес для всех — и для
> игроков из интернета, и для вас. Когда вы подключаетесь изнутри, пакет уходит на
> публичный IP вашей же сети и должен вернуться внутрь. Это работает только если роутер
> умеет **NAT hairpin** (он же NAT loopback). Многие домашние роутеры этого не умеют —
> и подключение просто не устанавливается, хотя снаружи сервер доступен.
>
> **Симптом, по которому это узнаётся:** сервер виден в браузере, снаружи к нему
> заходят, а вы с того же компьютера или из той же сети — нет. При этом в логе сервера
> нет ничего похожего на блокировку: до него пакеты просто не доходят.
>
> **Что делает вики.** Она прямо советует **оставлять `publicAddress` пустым**, чтобы
> адрес определялся автоматически, и отдельно упоминает литерал `"local"` —
> «возможно использовать ключевое слово `local`, чтобы автоматически определить
> локальный адрес сетевой карты». То есть механизм для этого случая в движке есть.
>
> **Варианты решения, от лучшего к рабочему:**
>
> 1. **Не указывать `publicAddress` вовсе** (оставить `""`). Так и рекомендует вики:
>    адрес определится сам. Это самый безопасный вариант для домашнего сервера.
> 2. **Проверить `"local"`.** Если сервер нужен только в локальной сети, литерал `"local"`
>    заставит его использовать локальный адрес. **Я это не проверял** — вики описывает
>    возможность, но не расписывает поведение; проверьте у себя.
> 3. **Включить NAT hairpin / NAT loopback на роутере**, если он это умеет.
> 4. **Настроить перенаправление с публичного IP на локальный**, как пришлось сделать мне.
>    Это работает, но требует, чтобы весь трафик к публичному IP заворачивался внутрь.
>
> **Чего делать не стоит:** указывать в `publicAddress` локальный адрес вида
> `192.168.x.x`, если сервер должен быть доступен из интернета. Тогда этот локальный
> адрес уйдёт в бэкенд как публичный, и внешние игроки его не достигнут. Локальный адрес
> уместен только для сервера, который заведомо работает лишь внутри сети, — как в
> примере из §7 (там `publicAddress` — `127.0.0.1`, потому что сервер тестовый).
>
> **Не пытайтесь «перебить» это параметром `-bindIP`:** он перекрывает **и**
> `bindAddress`, **и** `publicAddress`, то есть задаст тот же адрес ещё жёстче.

### 5.2 `a2s` — Steam Query (мониторинг, статистика)

| Ключ | Тип | По умолч. | Источник | Описание |
|---|---|---|---|---|
| `address` | string | — | `[вики]` | Помечен как **required**. IP, к которому привязан A2S-сокет. В реальном рабочем конфиге здесь `"0.0.0.0"`. |
| `port` | number 1..65535 | 17777 | `[вики]` | UDP-порт для A2S-запросов. |

> При неверном порте сервер не падает: в лог идёт
> `[A2S] Invalid port, set to default=17777...` `[бинарь]`.
> Если `a2s` не нужен вовсе — секцию можно не указывать.

### 5.3 `rcon` — удалённая консоль (опционально)

Вся секция помечена в вики как **Optional**. Полный разбор — права, список команд,
диагностика — в отдельном документе: [`ArmaReforger_RCON_RU.md`](ArmaReforger_RCON_RU.md).

| Ключ | Тип | По умолч. | Источник | Описание |
|---|---|---|---|---|
| `address` | string | — | `[вики]` | Помечен как **required**. IP, к которому привязан RCON-сокет. Для локального доступа — `"127.0.0.1"`. **Не выставляйте в `0.0.0.0` на сервере, доступном из интернета** — RCON даёт полный контроль над сервером. |
| `port` | number 1..65535 | 19999 | `[вики]` | Порт RCON. **Протокол (UDP или TCP) не подтверждён** — источники расходятся, см. [`ArmaReforger_RCON_RU.md`](ArmaReforger_RCON_RU.md) §1. При неверном значении — `[RCON] Invalid port, set to default=19999...` `[бинарь]`. |
| `password` | string | — | `[вики]` | **Обязателен для запуска RCON.** Без пробелов. Минимум 3 символа. |
| `maxClients` | number 1..16 | 16 | `[вики]` | Максимум одновременных RCON-клиентов. Отсутствует в шаблоне вики, но описан в тексте. |
| `permission` | string | — | `[вики]` | `"admin"` — любые команды; `"monitor"` — только не меняющие состояние (на практике только `#players`). |
| `blacklist` | array | `[]` | `[вики]` | Список команд, исключённых из выполнения. |
| `whitelist` | array | `[]` | `[вики]` | Если задан — разрешены только перечисленные команды. |

> RCON не умеет оповещать об отключении клиента: **после выхода клиента сервер держит
> соединение ещё 45 секунд** до таймаута, и всё это время слот `maxClients` занят.
> Если вы часто перезапускаете свой RCON-клиент, закрывайте его командой `@logout`
> или увеличивайте `maxClients`.

### 5.4 `game` — настройки игры

| Ключ | Тип | По умолч. | Источник | Описание |
|---|---|---|---|---|
| `name` | string 0..100 | — | `[вики]` | Имя сервера в браузере. Слишком длинное имя обрезается: `Session name exceed max value > N, cropped under limit...` `[бинарь]`. |
| `password` | string | `""` | `[вики]` | Пароль для подключения. Пусто = без пароля. |
| `passwordAdmin` | string | — | `[вики]` | Пароль администратора. Вход в игре: `#login <пароль>`. Без пробелов. |
| `admins` | array of string | `[]` | `[вики]` | identityId и/или steamId администраторов. С 1.3.0 — **не более 20 уникальных ID**. Такие игроки могут `#login` без пароля. Приоритетная очередь при входе работает только для IdentityId, не для SteamId. |
| `scenarioId` | string | — | `[вики]` | Путь к `.conf` сценария **вместе с GUID**. См. [`ArmaReforger_Scenarios_RU.md`](ArmaReforger_Scenarios_RU.md). |
| `maxPlayers` | number 1..128 | 64 | `[вики]` | Максимум игроков. |
| `visible` | bool | `true` (с 0.9.8.73) | `[вики]` | Показывать сервер в браузере. |
| `crossPlatform` | bool | `false` | `[вики]` | Если `true` — автоматически добавляет `PLATFORM_PC`, `PLATFORM_XBL`, `PLATFORM_PSN` в `supportedPlatforms`, если их там нет. |
| `supportedPlatforms` | array of string | `["PLATFORM_PC"]` | `[вики]` | Платформы, которые принимает сервер. См. §5.5. |
| `gameProperties` | object | — | `[вики]` | Настройки геймплея. См. §5.5. |
| `modsRequiredByDefault` | bool | `true` | `[вики]` | Значение `required` по умолчанию для всех модов. |
| `mods` | array of object | `[]` | `[вики]` | Список модов. См. §5.5.1. |
| `gameInstanceFiles` | — | — | `[бинарь]` | Есть в схеме 1.6.0.119, не документирован. |
| `fileReferences` | — | — | `[бинарь]` | То же. |

#### 5.4.1 `game.mods[]` — элементы массива

| Ключ | Тип | По умолч. | Описание |
|---|---|---|---|
| `modId` | string | — | **GUID мода, 16 hex-символов, без `{}`.** Из `addon.gproj`, строка `GUID`. Готовый список отдаёт сама игра — см. ниже. |
| `name` | string | — | **Не влияет ни на что.** Просто человекочитаемый комментарий. |
| `version` | string | — | Необязателен. Если не указан — берётся последняя версия мода. |
| `required` | bool | `true` или `modsRequiredByDefault` | Если `false` и мод не скачивается с Workshop — он автоматически убирается из списка с предупреждением в логе. |

Пример:

```json
"mods": [
  { "modId": "5DBD560C5148E1DA", "name": "ACECarrying", "version": "1.4.3" },
  { "modId": "60C4CE4888FF4621", "name": "ACECore" }
]
```

> Стабильность сервера требует, чтобы `modId` всех модов совпадали с тем, что
> установлено у клиентов. Расхождение версий ведёт к отказу подключения.

#### Как получить готовый список модов из игры

**Не набирайте `modId` руками — игра отдаёт готовый JSON.** Это штатный способ, и он
избавляет от опечаток в GUID.

1. Запустите игру (клиент), в главном меню нажмите иконку **модов** (пазл) в правом
   верхнем углу.
2. В открывшемся окне — **«Сохранённые настройки модов»**. Там три вкладки:
   **«Сохранённые установки»** (пресеты модов), **JSON** и **«Командная строка»**.
   Пресеты разобраны ниже — если модов много, начните с них.
3. Откройте вкладку **JSON** и нажмите **«Скопировать в буфер обмена»**.

Вы получите ровно те объекты, которые нужны полю `game.mods`.
**Ниже — дословный вид этого вывода, скопированный из буфера обмена.** Обратите внимание,
что он начинается сразу с `{` и заканчивается на `}`:

```text
{
  "modId": "5965550F24A0C152",
  "name": "Where Am I",
  "version": "1.2.0"
},
{
  "modId": "5DBD560C5148E1DA",
  "name": "ACE Carrying",
  "version": "1.4.3"
},
{
  "modId": "60C4CE4888FF4621",
  "name": "ACE Core",
  "version": "1.4.4"
}
```

> ### ⚠️ Это ещё не валидный JSON — добавьте квадратные скобки
>
> **Игра выдаёт список объектов, но не оборачивает его в массив.** То есть в начале нет
> `[`, а в конце нет `]`. Именно поэтому блок выше помечен как `text`, а не `json`:
> он **не является** корректным JSON, и парсер его не примет.
>
> Чтобы получилось значение для `game.mods`, оберните вставленное в квадратные скобки:
>
> ```json
> "mods": [
>   {
>     "modId": "5965550F24A0C152",
>     "name": "Where Am I",
>     "version": "1.2.0"
>   },
>   {
>     "modId": "5DBD560C5148E1DA",
>     "name": "ACE Carrying",
>     "version": "1.4.3"
>   }
> ]
> ```
>
> Обратите внимание на запятые: **между** объектами они нужны, после **последнего** —
> нет. Именно на этом месте чаще всего ломается конфиг после вставки списка модов.
>
> Без скобок конфиг не пройдёт схему и сервер напишет
> `Server Config file is Invalid - cannot start server!` — при этом сам текст от игры
> выглядит корректным, и это сбивает с толку. О проблеме знают и авторы контейнерных
> сборок: в их инструкциях отдельным шагом указано «добавить `[` сверху и `]` снизу,
> потому что игра не отдаёт валидный JSON».

Что полезно знать про сам вывод:

- `modId` уже **без фигурных скобок** — ровно в том виде, который требует конфиг;
- `version` заполняется автоматически, так что версии модов будут зафиксированы явно;
- `name` — просто комментарий, на работу не влияет;
- порядок модов значения не имеет.

#### Вкладка «Сохранённые установки» — пресеты модов

Первая вкладка того же окна, из которого вы копировали JSON, — это **пресеты (наборы)
модов**. Именно ею удобно готовить список для сервера, если модов много и они нужны
не все.

Что там есть:

- **«Создать новую настройку»** — добавить новый пресет.
- Список сохранённых пресетов с галочкой слева. Справа у каждого указано **число модов
  в нём** — так видно, что внутри, не открывая.
- Кнопки действий у выбранной строки: **сохранить**, **удалить**, **переименовать**,
  а внизу — **«Загрузить»**.

**Как это связано с менеджером модов.** Состав пресета задаётся в самом менеджере модов
(кнопка **«Менеджер модов»** внизу окна): там вы **включаете и выключаете** нужные моды
из общего списка установленных. Набранный набор сохраняется как пресет, и у него
появляется собственное число модов.

**Рабочий порядок действий** для сборки списка под сервер:

1. В менеджере модов включаете ровно те моды, которые будут на сервере.
2. Возвращаетесь в «Сохранённые установки», создаёте пресет (например `server`) и
   сохраняете его.
3. Выбираете этот пресет, нажимаете **«Загрузить»**.
4. Переходите на вкладку **JSON** и копируете список — в нём окажутся только моды
   выбранного пресета.

Смысл пресетов в том, что вы **не пересобираете список вручную каждый раз**: один пресет
для сервера, другой — для игры с друзьями без модов, третий — для теста конкретного мода.
Загрузка пресета переключает активный набор целиком.

> **Оговорка.** Названия вкладок и кнопок приведены так, как они видны в русской
> локализации клиента. Состав пресета я описываю по наблюдаемому поведению интерфейса
> (галочка, число модов, кнопка «Загрузить») — **внутреннюю логику хранения пресетов и то,
> что именно переключает галочка, я не проверял.** Если пресет ведёт себя не так, как
> ожидаете, ориентируйтесь на содержимое вкладки JSON: она всегда показывает то, что
> реально попадёт в конфиг.

#### Вкладка «Командная строка»

Третья вкладка того же окна даёт список модов **для параметра запуска `-addons`** —
это альтернатива полю `game.mods`. Список тоже зависит от выбранного пресета.

Помните о несовместимости: **`-addons` и `-config` вместе использовать нельзя**
(см. [`ArmaReforger_StartupParams_RU.md`](ArmaReforger_StartupParams_RU.md) §6).
Выбирайте что-то одно: либо моды в `server.json`, либо через параметр запуска.

### 5.5 `game.gameProperties`

| Ключ | Тип / диапазон | По умолч. | Источник | Описание |
|---|---|---|---|---|
| `serverMaxViewDistance` | number 500..10000 | 1600 | `[вики]` | Дальность прорисовки на сервере. |
| `serverMinGrassDistance` | number: `0` или `50..150` | 0 | `[вики]` | Минимальная дистанция травы в метрах. `0` = не навязывать клиентам. |
| `networkViewDistance` | number 500..5000 | 1500 | `[вики]` | Максимальная дальность сетевой передачи реплицируемых сущностей. |
| `fastValidation` | bool | `true` | `[вики]` | Быстрая проверка совпадения состояния карты у клиента и сервера. **Для публичного сервера всегда `true`.** |
| `battlEye` | bool | `true` | `[вики]` | Включить античит BattlEye. |
| `disableThirdPerson` | bool | `false` | `[вики]` | Запретить вид от третьего лица. |
| `VONDisableUI` | bool | `false` | `[вики]` | Отключить интерфейс голосового чата. |
| `VONDisableDirectSpeechUI` | bool | `false` | `[вики]` | Отключить интерфейс прямого голосового общения. |
| `VONCanTransmitCrossFaction` | bool | `false` | `[вики]` | `true` — можно передавать на радио других фракций; `false` — только слушать. |
| `missionHeader` | object | — | `[вики]` | Переопределяет `SCR_MissionHeaderCampaign` сценария. См. §5.5.2. |

**Про `fastValidation` подробно** `[вики]`. При `true` между сервером и клиентом
передаётся минимум данных, достаточный для проверки совпадения; при расхождении
нельзя понять, какая именно сущность различилась. При `false` передаются
дополнительные данные по каждой сущности и компоненту, и расхождение можно
локализовать. `false` имеет смысл только при локальной разработке
(сервер и клиент на одной машине). Для публичного сервера — `true`.

**Про `battlEye`.** Значение по умолчанию — `true`, но в реальном рабочем конфиге
(см. §7) часто стоит `false`. Если античит не нужен, отключение снижает нагрузку.

#### 5.5.1 `supportedPlatforms` — допустимые комбинации

Значения: `PLATFORM_PC`, `PLATFORM_XBL`, `PLATFORM_PSN`.

| Тип сервера | Допустимая комбинация |
|---|---|
| Ванильный | только PC |
| Ванильный | PC + Xbox + PlayStation (все три) |
| С модами | PC + Xbox (PlayStation не добавляется) |

**Недопустимые комбинации:** PC + только Xbox; PC + только PlayStation;
только Xbox; только PlayStation; Xbox + PlayStation.

#### 5.5.2 `missionHeader` — переопределение заголовка сценария

Вики описывает это поле одной фразой: «переопределяет `SCR_MissionHeaderCampaign`
сценария», и не приводит **никакого** списка ключей. Поэтому полный разбор вынесен
в отдельный документ: **[`ArmaReforger_MissionHeader_RU.md`](ArmaReforger_MissionHeader_RU.md)**.
Там все поля с типами, значениями по умолчанию и описаниями, добытые из исходников
классов, плюс рабочие примеры.

Коротко самое важное:

- `missionHeader` — это тот же объект, что лежит в `Missions/<Имя>.conf`. Движок
  накладывает указанные поля **поверх** прочитанных из сценария; остальные остаются
  как в сценарии.
- **Имена ключей — это имена полей класса**, а не строки из `.conf`.
  `World` и `SystemsConfig` сюда **не переносятся**: они только читаются из сценария.
- **Набор доступных полей зависит от класса заголовка сценария**:
  Conflict использует `SCR_MissionHeaderCampaign` (поля кампании — снабжение, базы,
  стартовое звание), Game Master — базовый `SCR_MissionHeader`, Combat Ops —
  `SCR_MissionHeaderCombatOps`. Ключ из чужого класса будет молча проигнорирован.
- Булевы поля пишите как `true`/`false` (в `.conf` сценариев они записаны как `0`/`1`).
- **Значения по умолчанию, приведённые в разборе, зависят от игрового режима**
  и не описывают текущее состояние вашего сервера. Это умолчания *класса*, а сценарий
  задаёт свои значения поверх них. Кроме того, логика части полей включается только
  в определённом режиме (например штабы и военные базы кампании существуют только
  в Conflict). Подробнее — §3.0 разбора.

Рабочий пример `[практика]` (реальный конфиг на 1.6.0.119, сервер стартовал
с `JSON is Valid`):

```json
"missionHeader": {
  "m_iStartingHQSupplies": 10000,
  "m_bRandomStartingDaytime": false,
  "m_iStartingHours": 1,
  "m_iStartingMinutes": 0,
  "m_bOverrideScenarioTimeAndWeather": true,
  "m_fXpMultiplier": 20.0,
  "m_eStartingRank": 6
}
```

`"m_eStartingRank": 6` — это `MAJOR`. Числовые значения всех званий
(`SCR_ECharacterRank`, 0..18) сведены в таблицу в
[`ArmaReforger_MissionHeader_RU.md`](ArmaReforger_MissionHeader_RU.md) §3.2;
`1` — `PRIVATE`, то есть ванильное поведение.

Сервер умеет читать отсюда значения нескольких типов: при неподдерживаемом типе
в лог идёт одна из строк `Server Config MissionHeader: Parameter '%s' is not
supported type!` или `... Item on index %d in parameter '%s' is invalid type!`
`[бинарь]`. Ошибка в этом блоке **не роняет сервер**, но параметр будет
проигнорирован — это и есть способ проверить, принят ли ключ.

### 5.7 Поля сессий и баз данных `[бинарь]`

Следующие ключи присутствуют в схеме 1.6.0.119, но **публично не документированы**.

Что здесь стоит отметить:

- Секции `operating` **нет вообще** — она целиком опциональна.
- `rcon.port` равен `12345`, а не стандартному `19999`. Это допустимо;

  затем `Starting RPL server, listening on address 0.0.0.0:2001, fastValidation=true`
  и `[RCON] Init, Ip address=127.0.0.1 and Port=12345`.

## 8. Типовые задачи → что менять

| Задача | Что менять |
|---|---|
| Сервер для своих, без пароля | `game.password: ""`, `game.visible: false` |
| Только по паролю | `game.password: "<пароль>"` |
| Сменить карту/режим | только `game.scenarioId` (из справочника) |
| Больше игроков | `game.maxPlayers` (максимум 128) |
| Только от первого лица | `gameProperties.disableThirdPerson: true` |
| Отключить голосовой интерфейс | `gameProperties.VONDisableUI: true`, `VONDisableDirectSpeechUI: true` |
| Радио между фракциями | `gameProperties.VONCanTransmitCrossFaction: true` |
| Меньше нагрузка на сеть | уменьшить `gameProperties.networkViewDistance` (минимум 500) |
| Убрать траву у клиентов | `gameProperties.serverMinGrassDistance: 0` |
| Отключить античит | `gameProperties.battlEye: false` |
| Снизить нагрузку от ИИ | `operating.aiLimit: <число>` или `operating.disableAI: true` |
| Очередь на вход | `operating.joinQueue.maxSize: <1..50>` |
| Удалённая консоль | добавить секцию `rcon` с `password` |
| Мониторинг сервера | секция `a2s` (порт 17777) |
| Модовый сервер | заполнить `game.mods[]` (GUID из `addon.gproj`) + `supportedPlatforms` без PSN |
| Консольные игроки | `game.crossPlatform: true` (PC + все консоли) |
| Свой сценарий из мода | `game.scenarioId` с GUID из `<Миссия>.conf.meta` |
| Фиксированное время суток | `missionHeader.m_iStartingHours` / `m_iStartingMinutes` (+ `m_bOverrideScenarioTimeAndWeather`) |
| Случайная погода | `missionHeader.m_bRandomStartingWeather`, `m_bRandomWeatherChanges` |
| Множитель опыта | `missionHeader.m_fXpMultiplier` |
| Лимиты по фракциям | `missionHeader.m_aFactionLimits` |
| Больше снабжения на старте | `missionHeader.m_iStartingHQSupplies` |
| Разрешить строительство баз | `missionHeader.m_bEstablishingBasesEnabled` |
| Стартовое звание игроков | `missionHeader.m_eStartingRank` — число `1`..`18` (`1` = PRIVATE, `6` = MAJOR) |

> Поля `missionHeader` работают не для всех сценариев: набор зависит от класса
> заголовка. Подробности и полные списки — в
> [`ArmaReforger_MissionHeader_RU.md`](ArmaReforger_MissionHeader_RU.md).

## 9. Проверка и частые ошибки

### Порядок проверки

1. **Проверьте JSON-синтаксис** любым валидатором (`jq`, редактор, онлайн-валидатор).
2. **Запустите сервер и прочитайте лог.** Ищите три строки:
   ```
   BACKEND : Loading dedicated server config.
   BACKEND : Server config loaded.
   BACKEND : JSON is Valid
   ```
   Третья строка — подтверждение, что схема принята.
3. **Проверьте, что сокет поднялся:**
   ```
   NETWORK : Starting RPL server, listening on address 0.0.0.0:2001, fastValidation=true
   ```
4. **Проверьте регистрацию в бэкенде:**
   ```
   BACKEND : Server registered with address: <IP>:<port>
   BACKEND : Direct Join Code: <код>
   ```
   `Direct Join Code` удобно сообщать игрокам — по нему можно подключиться напрямую.
5. **Проверьте RCON**, если он настроен:
   ```
   BACKEND : [RCON] Init, Ip address=127.0.0.1 and Port=12345
   ```
6. **Проверьте, что сценарий загрузился** — в логе появляется строка вида
   `WORLD : Entities load 'worlds/...'` и `RESOURCES : Loaded mission headers from N addon(s)!`.

Где лежат логи выделенного сервера:

```
<Dedicated Server>\<profile>\logs\logs_<дата>_<время>\console.log
<Dedicated Server>\<profile>\logs\logs_<дата>_<время>\error.log
<Dedicated Server>\<profile>\logs\logs_<дата>_<время>\script.log
```

Каталог `profile` задаётся параметром запуска `-profile`; по умолчанию — `profile`
рядом с исполняемым файлом.

### Таблица симптомов

| Симптом в логе | Причина | Что делать |
|---|---|---|
| `Server Config file is Invalid - cannot start server!` | JSON не прошёл схему | Проверить типы значений и регистр ключей |
| Окно `Missing Addon`: `Can't find '58D0FB3206B6F859' game addon!` | Запуск не из рабочей директории сервера | `cd` в каталог сервера перед запуском (см. §10) |
| Окно `Missing Addon` с **другим** GUID | Нет аддона, который требует сценарий или мод | Проверить, что аддон есть в `addons/` и в `game.mods` |
| Сервер виден и доступен снаружи, но **не пускает из своей локальной сети** | В `publicAddress` указан публичный IP, а роутер не умеет NAT hairpin | Убрать `publicAddress` (оставить `""`) или настроить перенаправление; см. §5.1 |
| `Session name exceed max value > N, cropped under limit...` | `game.name` слишком длинное | Сократить до 100 символов |
| `[A2S] Invalid port, set to default=17777...` | `a2s.port` вне диапазона | Задать 1..65535 |
| `[RCON] Invalid port, set to default=19999...` | `rcon.port` вне диапазона | Задать 1..65535 |
| `[RCON] Init failed... Missing password or password length < 3 characters !!!` | RCON не поднялся: пароль пуст или короче 3 символов | Задать `rcon.password` без пробелов, от 3 символов |
| `[RCON] Init failed... RCON is now turned off.` | Следствие строки выше — RCON выключен | Исправить пароль и перезапустить |
| `Server Config MissionHeader: Parameter 'X' is not supported type!` | Неподдерживаемый тип значения в `missionHeader` | Убрать параметр или сменить тип |
| `Server Config MissionHeader: Item on index N in parameter 'X' is invalid type!` | Неверный тип элемента массива в `missionHeader` | Проверить элементы массива |
| `Storage "X" contains undefined database named "Y"!` | `storages` ссылается на несуществующую запись в `databases` | Согласовать имена |
| RCON не отвечает, в логе нет `[RCON] Init` | Не задан `rcon.password`, либо пароль с пробелами / короче 3 символов | Исправить пароль |
| Порт открыт, но клиент не подключается | Сервер слушает не тот интерфейс | Проверить `bindAddress` |
| `Failed to fetch addon details from workshop API!` | Нет связи с Workshop API | Проверить интернет; неверный `modId` |
| `%d addons are not downloadable! Automatically removed as they have set "required" to false` | Мод недоступен и помечен необязательным | Это не ошибка — мод убран из списка |

### Чек-лист перед публикацией сервера

- [ ] `game.scenarioId` — GUID взят из справочника, а не придуман.
- [ ] `fastValidation: true`.
- [ ] `rcon.password` без пробелов, минимум 3 символа.
- [ ] `game.passwordAdmin` без пробелов.
- [ ] `game.name` не длиннее 100 символов.
- [ ] `supportedPlatforms` — допустимая комбинация.
- [ ] `game.mods[].modId` — GUID из `addon.gproj` (не `ID`), без фигурных скобок.
- [ ] `game.maxPlayers` ≤ 128.
- [ ] Открыты нужные UDP-порты.
- [ ] В логе есть `JSON is Valid`.
- [ ] Запуск с `-maxFPS` (см. §11).

## 10. Запуск сервера

> ### ⚠️ Сначала `cd` в каталог сервера
>
> **Запускать только из рабочей директории сервера.** Иначе он не найдёт собственную базу
> игры и покажет модальное окно:
>
> ```
> Missing Addon
> Can't find '58D0FB3206B6F859' game addon! Check setup guidelines!
> ```
>
> `58D0FB3206B6F859` — это GUID файла `addons\data\ArmaReforger.gproj`, то есть **самой
> игры**, а не вашего мода. Сервер ищет `.\addons\core` и `.\addons\data` относительно
> **текущего каталога**, а не относительно своего `.exe`. Ошибка возникает, если
> `ArmaReforgerServer.exe` запущен двойным щелчком из проводника или ярлыком с чужим
> «Рабочим каталогом».
>
> ```powershell
> cd "C:\Program Files (x86)\Steam\steamapps\common\Arma Reforger Server"
> .\ArmaReforgerServer.exe -config .\config.json -profile .\profile
> ```
>
> Проверка, что каталог верный: в `console.log` есть строка `Addon dirs:` с
> `dir: './addons'`, а следом `Available addons:` со списком
> `gproj: './addons/core/core.gproj'` и `gproj: './addons/data/ArmaReforger.gproj'`.
> Нет этих строк — рабочий каталог не тот.
>
> **Не путайте с похожими ошибками.** Здесь речь ровно про `game addon` с GUID
> `58D0FB3206B6F859`. Другой GUID в этом окне означает отсутствующий аддон вашего мода —
> это другая проблема.

```powershell
cd "C:\Program Files (x86)\Steam\steamapps\common\Arma Reforger Server"
.\ArmaReforgerServer.exe -config server.json -profile profile
```

> **Linux?** Установка через SteamCMD, скрипт запуска, `systemd`-юнит и специфичные для
> Linux грабли (регистр путей, права, протокол RCON) — в приложении А документа
> [`ArmaReforger_StartupParams_RU.md`](ArmaReforger_StartupParams_RU.md).
> Требование к рабочему каталогу там то же самое, только выражается через
> `WorkingDirectory=` в юните.

Переопределить параметры конфига можно командной строкой. Полный разбор — в
[`ArmaReforger_StartupParams_RU.md`](ArmaReforger_StartupParams_RU.md); здесь только
самое нужное:

| Параметр | Назначение |
|---|---|
| `-config <файл.json>` | Путь к конфигу |
| `-profile <каталог>` | Каталог профиля (логи, сохранения) |
| `-maxFPS <число>` | Ограничить FPS сервера (рекомендуется 60..120) |
| `-bindIP <IP>` | Перекрыть `bindAddress` и `publicAddress` |
| `-bindPort <порт>` | Перекрыть `bindPort` и `publicPort` |
| `-a2sPort <порт>` | Перекрыть порт A2S |
| `-a2sIpAddress <IP>` | Перекрыть адрес A2S |
| `-addons <GUID,...>` | Загрузить моды по GUID. **Несовместим с `-config`** |
| `-addonsDir <путь>` | Дополнительные каталоги модов |
| `-disableAI` | Отключить ИИ |
| `-aiLimit <число>` | Лимит ИИ (перекрывает `operating.aiLimit`) |
| `-disableCrashReport` | Отключить краш-репортер |
| `-disableNavmeshStreaming` | Отключить потоковую загрузку навмеша |
| `-logLevel <уровень>` | Уровень лога: `spam`…`fatal` — полезно при отладке |

> Замечания по именам, проверенным в бинарнике сборки 1.6.0.119:
> параметр называется **`-disableCrashReport`** (без `er`; в `server.json` при этом поле
> зовётся `operating.disableCrashReporter` — через `er`), и лимит ИИ — **`-aiLimit`**,
> а не `-AILimit`. Имена регистронезависимы, но строки должны совпадать по буквам.

> ⚠️ `-listScenarios` в серверном бинарнике 1.6.0.119 **отсутствует полностью**
> (проверено регистронезависимым поиском по строкам). Он живёт в клиентской ветке:
> в `scripts/Game/game.c` (метод `OnGameStart`) вызывает
> `SCR_GameLogHelper.LogScenariosConfPaths()`, то есть печатает список путей к `.conf`
> **в лог клиента**, а не в stdout. Запуск `ArmaReforgerServer.exe -listScenarios`
> списка не дал: в выводе были только ошибки обращения к бэкенду
> `[RestApi] TYPE:[GameConfig/List] Error - Cannot send request`, а список в лог не попал.
> Если хотите получить перечень на клиенте — запускайте игру с этим параметром
> и смотрите `console.log` в `logs/<сессия>/`.
> Готовый список с GUID уже есть в
> [`ArmaReforger_Scenarios_RU.md`](ArmaReforger_Scenarios_RU.md).

> ⚠️ Параметр `-server "<world>"` заставляет загрузить локальный мир,
> и **при этом конфиг игнорируется**.

## 11. Два важных правила эксплуатации

Оба взяты из вики и помечены там как «very important» для публичного хостинга:

1. **`fastValidation` должен быть `true`.** Иначе при подключении каждого клиента
   передаётся избыточный объём данных по всем реплицируемым сущностям и компонентам.
2. **Ограничивайте FPS сервера параметром `-maxFPS`.** Без него сервер попытается
   занять все доступные ресурсы CPU. Рекомендуемый диапазон — 60..120.

Дополнительно:

3. **BattlEye настраивается отдельным файлом** `battleye\BEServer_x64.cfg`.
   Там уже лежат строки `GameID armar` и `MasterPort 2001`.
   Свои настройки (`RConPort`, `RConPassword`) нужно **дописывать**, а не
   перезаписывать файл: при потере `GameID`/`MasterPort` игроки получают при входе
   сообщение `Missing GameID/MasterPort server config settings` и выкидываются,
   а изменённые значения ломают работу BattlEye.
4. **Не копируйте серверный конфиг между несовместимыми версиями игры** без проверки
   лога: набор полей менялся между версиями, и старые имена молча игнорируются.

  классов `SCR_MissionHeader`, `SCR_MissionHeaderCampaign` и `SCR_RankInfo`.
  Не извлечены состав `SCR_CampaignCustomBase`, поля `SCR_RankInfoCampaign` и пороги
  опыта для военных званий — они помечены как неизвестные.
- **Ревизия вики — март 2025, сборка сервера — январь 2026.** Поля, добавленные
  между этими датами, могли не попасть в вики. Именно поэтому в §5.5–§5.7 есть
  записи `[бинарь]` — это как раз такие поля. Обратная ситуация (поле есть в вики,
  но не читается сборкой) не наблюдалась: все ключи из вики в сборке 1.6.0.119
  присутствуют.
- Вики предупреждает, что «значения — строки, если не указано иное». Практика
  показывает, что числовые и булевы поля должны быть числами и булевыми:
  конфиг из §7 с числами и `true`/`false` проходит валидацию.
  Если сомневаетесь — сверяйтесь с §6.1 и §7.
- `/` в `scenarioId` для модовых миссий: путь указывается относительно корня аддона,
  GUID — из `<файл>.conf.meta`. Если `.meta` отсутствует, ресурс не зарегистрирован
  и сервер его не найдёт.

### Как проверить утверждения `[бинарь]` самостоятельно

Имена ключей и тексты ошибок ищутся в исполняемом файле сервера как обычные строки —
они не шифруются и не сжаты:

```powershell
$exe = "ArmaReforgerServer.exe"
$s = [System.Text.Encoding]::GetEncoding(28591).GetString([IO.File]::ReadAllBytes($exe))
$s.IndexOf("serverMaxViewDistance")   # -> смещение, либо -1 если строки нет
```

Полный список ключей схемы лежит одним непрерывным блоком (в сборке 1.6.0.119 —
по смещению `0x1A87640`), начинаясь строкой
`Server Config file is Invalid - cannot start server!`.
Готовый скрипт, который проверяет сразу список имён, — `tools/probe-keys.ps1`.
